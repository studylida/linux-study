## 복구 5회차: 프로세스와 작업 제어

- `sleep 20`을 포그라운드에서 실행해 명령이 끝날 때까지 셸이 기다리는 것을 확인했다.
- `sleep 60 &`와 `jobs -l`로 백그라운드 작업의 작업 번호와 PID를 확인했다. `fg %1`, `Ctrl+Z`, `bg %1`을 차례로 사용해 실행 위치와 상태를 바꿨다.
- 직접 시작한 프로세스에 PID로 기본 `TERM` 신호를 보내고 `jobs -l`이 비어 있는 것을 확인했다.
- 독립 실습에서 `sleep 120`을 백그라운드로 실행하고 `ps -p PID -o pid,stat,cmd`로 `S` 상태를 확인했다. 종료 후 같은 `ps` 명령에 제목 줄만 남는 것도 확인했다.

## 확인 결과

- 작업 번호는 현재 셸의 `jobs`, `fg`, `bg`에서 사용하고 PID는 운영체제의 프로세스를 `ps`로 조회하거나 `kill`로 제어할 때 사용한다고 설명했다.
- `Ctrl+Z`는 일시 정지, `kill -TERM PID`는 종료 요청이며 `bg`와 `fg`는 각각 백그라운드와 포그라운드에서 작업을 다시 실행한다고 설명했다.
- 독립 실습에서 `TERM PID`를 명령으로 입력했지만 `TERM`은 신호 이름이라는 점을 확인한 뒤 `kill -TERM PID`로 직접 고쳤다. 이 구분은 다음 관련 복습에서 다시 확인한다.
- 프로세스 실습 전에 `echo`와 `>`, `>>`, here-document로 파일을 작성했다. 파일 작성 자체가 아니라 터미널 명령과 스크립트 작성 지시의 구분에서 생긴 혼동임을 확인했다.
- 다음 회차: `printf` 형식 문자열을 짧게 복습한 뒤 파일 읽기, `grep`과 정규식을 진행한다.
