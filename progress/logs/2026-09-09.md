# 2026-09-09 학습 일지

## 복구 6회차: 파일 읽기, `grep`과 정규식

- 임시 디렉터리에서 INFO, WARN, ERROR가 섞인 8줄짜리 `app.log`를 만들고 `wc -l`로 줄 수를 확인했다.
- `head -n 3`과 `tail -n 2`로 파일의 앞부분과 뒷부분만 읽고 출력될 내용을 실행 전에 정확히 예상했다.
- 기본 `grep`의 `.`이 임의의 한 문자와 일치하는 결과를 `grep -F 'a.b'`의 고정 문자열 검색과 비교했다.
- `grep -En '^(ERROR|WARN)'`으로 ERROR 또는 WARN으로 시작하는 줄을 번호와 함께 찾고, `[0-9]`로 숫자가 포함된 줄을 찾았다.

## 확인 결과

- 첫 `printf` 실습에서는 명령을 기억하지 못해 `%s`와 `\n`의 역할과 빈칸 구조를 다시 확인했다.
- 세션 마지막에는 도움 없이 `printf '%s\n' 'READY' > check.txt`를 작성하고 `READY` 한 줄이 저장된 것을 확인했다. 기존 `printf` 오답은 복습 대기열에서 제거했다.
- 독립 확인에서 `grep -En '^(ERROR|WARN)' app.log`와 `grep -F 'a.b' app.log`를 직접 작성했고 예상한 줄만 출력됐다.
- 새 오답은 없었다.
