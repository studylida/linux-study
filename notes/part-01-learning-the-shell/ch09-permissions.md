# Ch.9: Permissions (권한)

## 오늘 배울 것

오늘은 리눅스의 **파일 권한 시스템**을 배울 거야. "누가 이 파일을 읽을 수 있는가? 수정할 수 있는가? 실행할 수 있는가?"를 제어하는 방법이야. 리눅스는 **멀티유저 시스템**이라 이게 정말 중요해!

---

## 핵심 개념

모든 파일과 디렉토리에 대해 3가지를 제어해:
- **누가**: owner(소유자) / group(그룹) / others(그 외 모든 사람)
- **뭘**: read(읽기) / write(쓰기) / execute(실행)
- **허용 여부**: 허용 / 거부

---

## 권한 읽는 법

`ls -l` 하면 왼쪽에 이런 게 보이지:

```
-rwxr-xr-x
│ │   │   │
│ │   │   └── others: r-x (읽기 O, 쓰기 X, 실행 O)
│ │   └────── group:  r-x (읽기 O, 쓰기 X, 실행 O)
│ └────────── owner:  rwx (읽기 O, 쓰기 O, 실행 O)
└──────────── 파일 타입 (- = 일반파일, d = 디렉토리, l = 심볼릭 링크)
```

각 문자의 의미: `r` = read(4), `w` = write(2), `x` = execute(1), `-` = 없음(0)

괄호 안의 숫자는 8진수 표기법에서 쓰는 값이야 — 아래에서 배울 거야.

---

## 권한 체크 순서

리눅스가 "이 사람이 이 파일에 접근해도 되나?" 판단하는 순서:

```
1. owner인가?  → YES → owner 권한 적용 (여기서 끝!)
2. group에 속해있나?  → YES → group 권한 적용
3. 둘 다 아니면 → others 권한 적용
```

중요한 점: owner이면서 group에도 속해있어도 **owner 권한만** 적용돼. 첫 번째 매칭에서 끝이야!

---

## group이란?

그룹은 사용자들을 묶어놓은 **팀** 같은 거야:

- 파일에는 그룹이 **딱 1개만** 지정됨
- 나는 여러 그룹에 속할 수 있지만, 파일의 그룹에 내가 속해있느냐만 중요해
- `id` 또는 `groups` 명령어로 내가 어느 그룹에 속해있는지 확인 가능

---

## chmod — 권한 변경

### 숫자(8진수) 방식

r=4, w=2, x=1을 더해서 표현해:

```bash
chmod 755 file   # rwxr-xr-x (소유자 전부, 나머지 읽기+실행)
chmod 644 file   # rw-r--r-- (소유자 읽기+쓰기, 나머지 읽기만)
chmod 600 file   # rw------- (소유자만 읽기+쓰기)
chmod 700 dir/   # rwx------ (소유자만 전부)
```

### 기호 방식

누구한테 뭘 할지 직관적으로 쓰는 방법:

```
누구: u(owner) g(group) o(others) a(all)
동작: +(추가) -(제거) =(설정)
권한: r w x
```

```bash
chmod u+x file       # 소유자에게 실행 권한 추가
chmod g-w file       # 그룹에서 쓰기 권한 제거
chmod o-rwx file     # 그 외 전부 제거
chmod a+r file       # 모두에게 읽기 추가
```

### 언제 뭘 쓰지?

- **숫자**: 권한을 **통째로** 설정할 때 → `chmod 755`
- **기호**: 특정 권한만 **하나 추가/제거**할 때 → `chmod u+x`

---

## 자주 쓰는 권한 패턴

이 3개만 외우면 대부분 커버돼:

```bash
chmod 755 script.sh   # 스크립트를 실행 가능하게 (가장 흔함)
chmod 644 file.txt    # 일반 파일 기본 권한
chmod 600 id_rsa      # 비밀 파일 — 나만 접근 가능
```

---

## sudo — 관리자 권한으로 명령어 실행

```bash
sudo cat /etc/sudoers   # 이 명령어 하나만 root 권한으로 실행
```

- **S**uper **U**ser **Do** — "관리자 권한으로 해줘"
- 비밀번호 입력 후 약 5분간 유지
- 실무에서 가장 많이 쓰는 방법

---

## su — 사용자 전환

```bash
su            # root로 전환
su - 영희     # 영희로 전환
exit          # 원래 사용자로 돌아오기
```

근데 실무에서는 거의 안 써. sudo가 훨씬 안전하니까.

### sudo vs su 비교

| | sudo | su |
|---|------|-----|
| 범위 | 명령어 **하나만** 관리자로 | 사용자 **통째로** 전환 |
| 안전성 | 더 안전 | 덜 안전 |
| 실무에서 | 주로 사용 | 거의 안 씀 |

---

## chown — 소유자/그룹 변경

```bash
sudo chown 영희 file.txt          # 소유자만 변경
sudo chown 영희:개발팀 file.txt    # 소유자 + 그룹 변경
sudo chown :개발팀 file.txt        # 그룹만 변경
```

`chown` = **ch**ange **own**er. sudo가 필요한 이유는 아무나 소유권을 바꾸면 남의 파일을 가로챌 수 있으니까!

---

## 정리

오늘 배운 핵심:
- 권한은 **owner/group/others** × **r/w/x** 조합
- 권한 체크는 owner → group → others 순서 (첫 매칭에서 끝)
- `chmod 755` (숫자) 또는 `chmod u+x` (기호)로 권한 변경
- **외울 3개**: 755(스크립트), 644(일반파일), 600(비밀파일)
- `sudo` = 명령어 하나만 관리자로, `su` = 통째로 전환
- `chown`으로 소유자/그룹 변경 (sudo 필요)
