# Ch.4.5: 파일명 작명법

## 오늘 배울 것

리눅스에서 **파일 이름을 어떻게 지어야 하는지**, 그리고 **나쁜 파일명이 왜 위험한지** 알아볼 거야. 이건 짧지만 중요한 내용이야!

---

## 리눅스 파일명 기본 규칙

- **대소문자 구분**: `File.txt`와 `file.txt`는 다른 파일이야
- **숨김 파일**: `.`으로 시작하면 숨김 처리 (`.bashrc` 같은 거)
- **확장자에 특별한 의미 없음**: 그냥 관례일 뿐. 리눅스는 파일 내용으로 판단해
- **최대 길이**: 255자

---

## 좋은 파일명 규칙

| 규칙 | 좋은 예 | 나쁜 예 |
|------|--------|--------|
| 공백 대신 `-` 또는 `_` | `my-report.txt` | `my report.txt` |
| 소문자 사용 | `my-report.txt` | `MyReport.txt` |
| 안전한 문자만 | `report-v2.txt` | `report&(v2).txt` |
| 날짜는 YYYY-MM-DD | `report-2026-01-30.txt` | `report-1-30-26.txt` |
| `-`로 시작하지 않기 | `backup.tar` | `-backup.tar` |

---

## 나쁜 파일명이 왜 위험해?

이 부분이 진짜 중요해. 잘못된 이름은 **명령어를 엉뚱하게 동작**시킬 수 있거든:

### 공백이 있으면 — 여러 파일로 해석됨

```bash
rm my report.txt    # "my"와 "report.txt" 두 파일을 삭제하려고 함!
```

### `-`로 시작하면 — 옵션으로 해석됨

```bash
rm -file.txt        # -f, -i, -l, -e 옵션으로 해석되어 버림!
```

### 특수문자가 있으면 — 셸 문법과 충돌

```bash
touch hello;rm -rf ~   # 세미콜론이 명령어 구분자라서 뒤의 rm도 실행됨!
```

이런 걸 **명령어 주입**이라고 하는데, 보안 사고로도 이어질 수 있어.

---

## 이미 공백이 있는 파일은 어떻게 다루지?

이미 공백이 있는 파일이 있으면 두 가지 방법이 있어:

```bash
# 방법 1: 따옴표로 감싸기
cp "my file.txt" backup/

# 방법 2: 백슬래시로 이스케이프
cp my\ file.txt backup/
```

팁: **Tab 자동완성**을 쓰면 자동으로 이스케이프 처리해줘!

---

## `-`로 시작하는 파일은?

```bash
rm -- -file.txt     # -- 뒤는 전부 파일명으로 해석해줘
rm ./-file.txt      # 앞에 경로를 붙여서 해결
```

`--`는 "여기서부터는 옵션이 아니라 파일명이야"라고 알려주는 약속이야.

---

## 정리

- 파일명은 **소문자, `-`/`_` 사용, 특수문자 피하기**
- 공백/특수문자가 있으면 따옴표나 `\`로 처리
- `-`로 시작하는 파일은 `--`나 `./` 붙여서 다루기
- 나쁜 파일명은 보안 위험까지 될 수 있으니 처음부터 잘 짓자!
