# Ch.3: Exploring the System

## 오늘 배울 것

지난번에 `ls`, `cd`, `pwd`로 돌아다니는 법을 배웠지? 오늘은 **파일과 디렉토리를 자세히 들여다보는 방법**을 배울 거야. `ls`의 숨겨진 기능들, 파일 유형을 알려주는 `file`, 그리고 긴 파일을 편하게 읽는 `less`까지!

---

## ls 명령어 심화

`ls`를 그냥 치면 파일 이름만 나오잖아. 근데 옵션을 붙이면 훨씬 많은 정보를 볼 수 있어:

| 옵션 | 하는 일 |
|------|---------|
| `-l` | 자세한 정보 (긴 형식) |
| `-a` | 숨김 파일까지 전부 보기 |
| `-h` | 크기를 KB, MB로 읽기 쉽게 |
| `-t` | 수정 시간순 정렬 |
| `-r` | 역순 정렬 |
| `-S` | 파일 크기순 정렬 |

옵션은 합쳐서 쓸 수 있어: `ls -lah`면 자세히 + 숨김파일 + 읽기 쉬운 크기 전부 한번에!

### ls -l 출력 읽는 법

`ls -l`을 치면 이런 게 나와:

```
drwxr-xr-x  5  user  group  4096  Jan 30 10:00  Documents
│           │  │     │      │     │             │
│           │  │     │      │     │             └─ 이름
│           │  │     │      │     └─ 수정 날짜/시간
│           │  │     │      └─ 파일 크기 (바이트)
│           │  │     └─ 그룹
│           │  └─ 소유자
│           └─ 링크 수
└─ 파일 유형 + 권한
```

맨 앞 첫 글자가 중요해:
- `d` = 디렉토리
- `-` = 일반 파일
- `l` = 심볼릭 링크 (바로가기 같은 거)

## file 명령어 — "이 파일 뭐야?"

리눅스는 윈도우랑 달라서 확장자로 파일 유형을 결정하지 않아. `.txt`라고 해놓고 실제로는 이미지 파일일 수도 있는 거지. `file` 명령어는 파일의 **실제 내용**을 분석해서 뭔지 알려줘:

```bash
file document.txt      # Unicode text, UTF-8 text
file /bin/ls           # Mach-O 64-bit executable (실행 파일)
file video.mp4         # ISO Media, MP4 Base Media
file /home             # directory
```

이런 상황에서 쓰면 좋아:
- 확장자 없는 파일이 뭔지 모를 때
- 다운받은 파일이 진짜 그 형식인지 의심될 때
- 텍스트 파일인지 바이너리인지 구분하고 싶을 때

## less 명령어 — 파일을 편하게 읽기

`cat`으로 파일을 보면 내용이 쫙 흘러가버려서 긴 파일은 보기 어렵잖아. `less`는 **페이지 단위로** 위아래 이동하면서 볼 수 있어:

```bash
less /etc/bashrc
```

### less 안에서 쓰는 키

| 키 | 동작 |
|----|------|
| `Space` 또는 `f` | 다음 페이지 |
| `b` | 이전 페이지 |
| `↑`/`↓` 또는 `j`/`k` | 한 줄씩 이동 |
| `g` | 파일 맨 처음으로 |
| `G` | 파일 맨 끝으로 |
| `/단어` | 단어 검색 |
| `n` | 다음 검색 결과 |
| **`q`** | **종료 — 이거 안 누르면 못 나와!** |

`less`에 들어가면 별도의 화면이 열리는데, 반드시 `q`를 눌러야 나올 수 있어. 참고로 이름의 유래는 "Less is more" — `more`라는 이전 명령어보다 기능이 많다는 뜻이야.

## 심볼릭 링크 (Symbolic Link)

윈도우의 "바로가기"와 같은 개념이야. 실제 파일이 아니라 **다른 곳을 가리키는 포인터**지.

### 왜 필요할까?

- 긴 경로를 짧게 단축하고 싶을 때
- 버전 관리할 때 (예: `python` → `python3.9`)
- 호환성을 유지하면서 실제 위치를 바꿀 때

### 확인하는 법

```bash
ls -l /tmp
# lrwxr-xr-x  ...  /tmp -> private/tmp
# │                 │       │
# │                 │       └─ 실제 위치
# │                 └─ 심볼릭 링크 이름
# └─ 'l' = 심볼릭 링크라는 표시
```

### 만드는 법

```bash
ln -s 원본경로 링크이름
ln -s /home/me/documents/important-file.txt ~/quick-access
```

## 주요 시스템 디렉토리

리눅스에는 디렉토리마다 역할이 정해져 있어. 전부 외울 필요는 없고, "이런 게 있구나" 정도로 알아두면 돼:

| 디렉토리 | 역할 |
|----------|------|
| `/` | 루트, 모든 것의 시작 |
| `/bin` | 필수 실행 파일 (ls, cp 등) |
| `/boot` | 부팅에 필요한 파일 |
| `/dev` | 장치 파일 (디스크, 키보드 등) |
| `/etc` | 시스템 설정 파일 |
| `/home` | 사용자들의 홈 디렉토리 |
| `/lib` | 공유 라이브러리 |
| `/root` | root 사용자의 홈 |
| `/tmp` | 임시 파일 |
| `/usr` | 사용자 프로그램, 문서 |
| `/var` | 로그, 메일 등 바뀌는 데이터 |

## 정리

오늘 배운 핵심:
- `ls -l`로 파일의 자세한 정보를 볼 수 있고, 옵션 조합(`-lah`)이 가능
- `file` 명령어로 파일의 실제 유형을 확인
- `less`로 긴 파일을 페이지 단위로 읽기 (`q`로 나가기!)
- **심볼릭 링크** = 바로가기, `ln -s`로 만듦
- 리눅스 디렉토리마다 정해진 역할이 있음
