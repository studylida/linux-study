# Ch.6: Redirection

## 오늘 배울 것

오늘은 리눅스에서 정말 강력한 기능인 **리다이렉션과 파이프**를 배울 거야. 명령어의 출력을 파일에 저장하거나, 한 명령어의 결과를 다른 명령어에 넘기는 방법이야. 이걸 알면 리눅스 활용 능력이 확 올라가!

---

## 표준 스트림 — 데이터가 흐르는 3개의 통로

모든 프로그램에는 3개의 데이터 통로가 있어:

| 이름 | 번호(fd) | 기본 연결 | 역할 |
|------|----------|----------|------|
| stdin | 0 | 키보드 | 프로그램에 들어오는 데이터 |
| stdout | 1 | 화면 | 정상 결과 출력 |
| stderr | 2 | 화면 | 에러 메시지 출력 |

stdout과 stderr는 둘 다 화면에 나오지만, **서로 다른 통로**야. 이게 핵심이야 — 나중에 에러만 따로 처리할 수 있거든.

---

## 리다이렉션 기호 총정리

한눈에 보면 이래:

| 기호 | 의미 | 예시 |
|------|------|------|
| `>` | stdout → 파일 (덮어쓰기) | `ls > file.txt` |
| `>>` | stdout → 파일 (이어쓰기) | `echo "hi" >> file.txt` |
| `<` | 파일 → stdin | `cat < file.txt` |
| `2>` | stderr → 파일 | `cmd 2> error.txt` |
| `> file 2>&1` | stdout + stderr → 파일 | 순서 중요! |
| `&>` | stdout + stderr → 파일 (축약) | `cmd &> all.txt` |
| `\|` | stdout → 다음 명령어의 stdin | `ls \| grep zip` |

---

## `>` vs `>>` — 덮어쓰기 vs 이어쓰기

이건 확실히 구분해야 해:

```bash
echo "AAA" > file.txt    # file.txt에 "AAA" (파일 새로 만듦)
echo "BBB" > file.txt    # file.txt에 "BBB" (AAA가 사라짐!)
echo "CCC" >> file.txt   # file.txt에 "BBB\nCCC" (뒤에 추가)
```

- `>`는 **무조건 덮어써**. 기존 내용이 싹 날아가!
- `>>`는 **뒤에 붙여**. 기존 내용은 그대로.
- 팁: `> file.txt`만 쓰면 파일 내용을 비울 수 있어 (내용 없이 덮어쓰기)

---

## 에러 리다이렉션 — `2>`

에러 메시지만 따로 파일로 보낼 수 있어:

```bash
ls /없는폴더 2> error.txt       # 에러만 파일로
ls /usr/bin /없는폴더 > ok.txt 2> err.txt  # 정상 출력과 에러를 따로따로
```

---

## `2>&1` — 순서가 핵심!

`2>&1`의 의미: "stderr를 stdout이 **지금 현재** 가리키는 곳으로 보내라."

### `> file 2>&1` (올바른 순서)

```
① > file      → stdout을 파일로 변경
② 2>&1        → stderr를 stdout이 가는 곳(=파일)으로 → 둘 다 파일!
```

### `2>&1 > file` (의도와 다른 결과!)

```
① 2>&1        → stderr를 stdout이 가는 곳(=화면)으로 → 아직 변화 없음
② > file      → stdout만 파일로 변경 → stderr는 여전히 화면!
```

순서에 따라 결과가 완전히 달라져! 헷갈리면 그냥 **`&>`를 쓰는 게 간단해**.

---

## `/dev/null` — 블랙홀

```bash
ls /없는폴더 2> /dev/null    # 에러 메시지 숨기기
```

`/dev/null`은 여기로 보내면 그냥 사라지는 특수 파일이야. "에러는 신경 안 쓸래"할 때 쓰면 돼.

---

## 파이프: `|` — 명령어를 연결하는 마법

파이프는 한 명령어의 stdout을 **다음 명령어의 stdin으로** 연결해줘:

```bash
ls /usr/bin | wc -l              # 파일 개수 세기
ls /usr/bin | sort | head -10    # 정렬 후 앞 10개만
ls /usr/bin | grep zip           # "zip" 포함된 것 찾기
ls /usr/bin | sort | uniq | wc -l  # 중복 제거 후 개수
```

이게 리눅스의 핵심 철학이야 — 작은 도구들을 파이프로 연결해서 복잡한 작업을 해내는 거지.

---

## 파이프와 같이 쓰면 좋은 명령어들

| 명령어 | 역할 | 예시 |
|--------|------|------|
| `cat` | 파일 출력/합치기 | `cat a.txt b.txt > merged.txt` |
| `sort` | 정렬 | `sort file.txt` |
| `uniq` | 연속된 중복 제거 | `sort data.txt \| uniq` |
| `wc` | 줄/단어/바이트 수 | `wc -l file.txt` |
| `grep` | 패턴 검색 | `grep "error" log.txt` |
| `head` | 앞부분 보기 | `head -5 file.txt` |
| `tail` | 뒷부분 보기 | `tail -5 file.txt` |
| `tee` | 화면 + 파일 동시 출력 | `ls \| tee output.txt` |

### tee — 화면에도 보면서 파일에도 저장

```bash
ls /usr/bin | tee allfiles.txt | grep zip
```

`tee`는 파이프 중간에 끼워서 **한쪽은 파일로 저장하고, 다른 쪽은 계속 파이프로 흘려보내**는 역할이야. 파일명을 인자로 받아 (`>`가 아니라!).

---

## 정리

오늘 배운 핵심:
- **3개의 스트림**: stdin(입력), stdout(출력), stderr(에러)
- `>`(덮어쓰기)와 `>>`(이어쓰기) 차이 확실히!
- `2>&1`은 **순서가 중요** — 헷갈리면 `&>` 쓰기
- `/dev/null`은 블랙홀 — 버리고 싶은 출력을 보내는 곳
- **파이프(`|`)**로 명령어를 체인처럼 연결
