# 3주 Linux·Bash 실력 복구 과정

## 목표

3주 동안 주 5회, 회당 30분씩 총 15회 연습한다. 과정이 끝나면 Codex가 정답 명령을 알려주지 않아도 간단한 파이프라인을 만들고, 입력을 검사하며 결과와 오류를 구분하는 짧은 Bash 스크립트를 작성할 수 있어야 한다.

셋째 주에 Bash 스크립트의 기초를 미리 사용하지만 Ch.28 이후의 정식 완료 상태는 바꾸지 않는다. 복구가 끝나면 Ch.28부터 다시 시작하고, 이미 익힌 내용은 짧은 독립 실습으로 확인한 뒤 진행한다.

## 한 회차 진행 방법

1. 5분 동안 이전 회차에서 막힌 작업 하나를 다시 수행한다. 첫 회차에는 오늘 다룰 상황과 완료 상태를 확인한다.
2. 20분 동안 현재 상태, 선택할 명령, 예상 결과를 말한 뒤 직접 실습한다.
3. 5분 동안 명령을 보지 않고 핵심 작업을 다시 수행하고 결과가 나온 이유를 설명한다.

첫 시도에는 정답 명령을 보여주지 않는다. 막히면 다음 순서로 한 단계씩 힌트를 제공한다.

1. 입력, 출력, 바뀌어야 할 상태를 짚는 개념 힌트를 준다.
2. 명령과 옵션 자리를 빈칸으로 둔 구조를 보여준다.
3. 최소 정답 예제를 보여준 뒤 예제를 닫고 같은 작업을 다시 작성하게 한다.

힌트를 받은 것은 실패로 취급하지 않는다. 다만 세션 마지막에 핵심 작업을 보지 않고 다시 수행하고 설명해야 해당 회차를 완료한다.

## 안전한 실습 환경

매회 다음 명령으로 새 임시 디렉터리를 만들고 출력된 경로 안에서만 파일을 생성하거나 변경한다.

```bash
linux_recovery_dir="$(mktemp -d)"
cd "$linux_recovery_dir"
pwd
```

- `sudo`, 실제 원격 서버, 시스템 설정 변경, `systemd` 조작은 사용하지 않는다.
- 삭제 대상은 먼저 출력하고 확인한다. 삭제 연습은 임시 디렉터리 안의 파일로 제한한다.
- 프로세스 종료는 실습에서 직접 시작한 프로세스만 대상으로 하며 기본 `TERM` 신호를 먼저 사용한다.
- 로컬 서버는 1024보다 큰 포트에서 실행하고 세션이 끝나기 전에 종료한다.

## 1주 차: 셸 기본기

### 1회차: 경로와 안전한 파일 작업

**목표**: 현재 위치와 작업 대상을 확인한 뒤 파일과 디렉터리를 안전하게 만들고 복사하고 이동하고 삭제한다.

**상황 실습**: `inbox`, `work`, `archive` 디렉터리와 이름이 다른 파일 여러 개를 만든다. 상대 경로와 절대 경로를 각각 사용해 선택한 파일을 복사하고 이름을 바꾸며, 삭제 전에 대상을 확인한다.

**독립 재현**: 새 구조에서 `.log` 파일만 `archive`로 복사하고 원본이 남아 있는지 확인한다. 공백이 있는 파일 이름도 안전하게 처리한다.

**완료 기준**: `pwd`, `cd`, `ls`, `mkdir`, `cp`, `mv`, `rm`을 상황에 맞게 선택하고 절대 경로와 상대 경로의 차이를 설명한다.

**참고 노트**: [Ch.2 Navigation](../notes/part-01-learning-the-shell/ch02-navigation.md), [Ch.4 Manipulating Files and Directories](../notes/part-01-learning-the-shell/ch04-manipulating-files-and-directories.md)

### 2회차: 확장, 따옴표, 변수와 `PATH`

**목표**: 셸이 명령을 실행하기 전에 와일드카드, 변수와 명령 치환을 어떻게 확장하는지 이해하고 따옴표로 결과를 제어한다.

**상황 실습**: 공백과 `*` 문자가 포함된 파일 이름을 만들고 의도한 파일만 선택한다. 작업 디렉터리를 셸 변수에 저장하고 날짜가 들어간 결과 디렉터리를 만든다. 명령이 실행 파일을 찾는 위치도 확인한다.

**독립 재현**: 변수에 저장된 공백 포함 경로로 이동하고, `.txt` 파일 목록과 현재 날짜를 조합한 결과 파일을 만든다.

**완료 기준**: 작은따옴표와 큰따옴표의 차이, `$variable`, `$(command)`, 셸 변수와 환경변수, `export`와 `PATH`의 역할을 자신의 말로 설명한다.

**참고 노트**: [Ch.7 Seeing the World as the Shell Sees It](../notes/part-01-learning-the-shell/ch07-seeing-the-world-as-the-shell-sees-it.md), [Ch.11 The Environment](../notes/part-02-configuration-and-environment/ch11-the-environment.md)

### 3회차: 표준 스트림, 리다이렉션과 파이프

**목표**: stdin, stdout, stderr를 구분하고 명령의 정상 결과와 오류를 파일이나 다음 명령으로 보낸다.

**상황 실습**: 존재하는 경로와 존재하지 않는 경로를 한 명령에서 조회한다. 정상 출력과 오류를 서로 다른 파일에 저장한 뒤 한 파일로 합친다. 파일 목록에서 원하는 항목만 골라 개수를 센다.

**독립 재현**: 정상 출력은 `result.txt`, 오류는 `error.txt`에 저장하고, 결과에서 특정 확장자만 찾아 정렬한 뒤 개수를 출력한다.

**완료 기준**: `>`, `>>`, `2>`, `2>&1`, `|`의 역할과 `> file 2>&1`에서 순서가 중요한 이유를 설명한다.

**참고 노트**: [Ch.6 Redirection](../notes/part-01-learning-the-shell/ch06-redirection.md)

### 4회차: 링크, 권한과 실행

**목표**: 파일 종류와 권한을 읽고 필요한 사용자에게만 읽기, 쓰기, 실행 권한을 부여한다.

**상황 실습**: 원본 파일의 하드 링크와 심볼릭 링크를 만들고 원본 이름을 바꿨을 때 차이를 확인한다. 일반 파일은 `640`, 실행 파일은 `750`으로 설정하고 `ls -l` 결과를 해석한다.

**독립 재현**: 새 스크립트 파일에 소유자만 쓰고 실행할 수 있으며 그룹은 읽고 실행할 수 있는 권한을 설정한다. 심볼릭 링크를 통해 같은 파일을 실행한다.

**완료 기준**: 하드 링크와 심볼릭 링크의 차이, owner·group·others와 `rwx`, `chmod 640`과 `chmod 750`을 설명한다.

**참고 노트**: [Ch.4 Manipulating Files and Directories](../notes/part-01-learning-the-shell/ch04-manipulating-files-and-directories.md), [Ch.9 Permissions](../notes/part-01-learning-the-shell/ch09-permissions.md)

### 5회차: 프로세스와 작업 제어

**목표**: 실행 중인 프로세스와 현재 셸의 작업을 구분하고 안전하게 상태를 바꾸거나 종료한다.

**상황 실습**: 시간이 오래 걸리는 명령을 포그라운드와 백그라운드에서 실행한다. 작업을 정지하고 다시 시작하며 PID와 작업 번호를 각각 확인한다.

**독립 재현**: 직접 시작한 `sleep` 프로세스를 백그라운드에서 확인하고 기본 `TERM` 신호로 종료한 뒤 사라졌는지 검증한다.

**완료 기준**: `&`, `Ctrl+Z`, `bg`, `fg`, `jobs`, `ps`, `kill`을 상황에 맞게 사용하고 작업 번호와 PID의 차이를 설명한다.

**참고 노트**: [Ch.10 Processes](../notes/part-01-learning-the-shell/ch10-processes.md)

## 2주 차: 텍스트 처리와 파이프라인

### 6회차: 파일 읽기, `grep`과 정규식

**목표**: 큰 파일의 필요한 부분만 읽고 고정 문자열과 정규식 검색을 구분한다.

**상황 실습**: INFO, WARN, ERROR가 섞인 예제 로그를 만든다. 앞뒤 일부를 확인하고 줄 수를 센 뒤, 고정 문자열과 두 가지 오류 상태를 각각 검색한다.

**독립 재현**: ERROR 또는 WARN으로 시작하는 줄만 줄 번호와 함께 찾고, 고정 문자열 `a.b`를 정규식으로 해석하지 않고 검색한다.

**완료 기준**: `head`, `tail`, `wc`, `grep -F`, `grep -E`를 선택하고 `^`, `.`, `[]`가 패턴에서 하는 일을 설명한다.

**참고 노트**: [Ch.15 Reading Files](../notes/part-03-common-tasks/ch15-reading-files.md), [Ch.22 Regular Expressions](../notes/part-03-common-tasks/ch22-regular-expressions.md), [Ch.23 grep](../notes/part-03-common-tasks/ch23-grep-mastery.md)

### 7회차: 정렬, 빈도 계산과 `tee`

**목표**: 여러 작은 명령을 연결해 데이터의 빈도와 상위 결과를 계산하고 중간 결과를 저장한다.

**상황 실습**: 상태 코드가 반복되는 예제 로그에서 코드만 추출한다. 정렬과 중복 집계를 거쳐 빈도가 높은 순서로 상위 세 개를 출력하고 전체 목록도 파일로 남긴다.

**독립 재현**: 최소 네 단계의 파이프라인으로 오류 코드별 횟수를 계산하고 `tee`를 사용해 화면과 파일에 동시에 출력한다.

**완료 기준**: `sort`, `uniq -c`, `tr`, `tee`, `head`의 입력과 출력을 설명하고 파이프라인 순서를 바꾸면 결과가 달라지는 이유를 말한다.

**참고 노트**: [Ch.15 Reading Files](../notes/part-03-common-tasks/ch15-reading-files.md), [Ch.16 Piping과 tr](../notes/part-03-common-tasks/ch16-piping-tr.md)

### 8회차: `find`, `-exec`와 `xargs`

**목표**: 이름, 종류, 깊이와 시간을 조건으로 파일을 찾고 실제 작업 전에 대상을 검증한다.

**상황 실습**: 여러 하위 디렉터리에 오래된 로그와 새 로그를 만든다. 조건에 맞는 파일을 먼저 출력하고, 결과를 한 번에 다른 디렉터리로 옮긴다. 공백이 있는 파일 이름도 포함한다.

**독립 재현**: 시작 디렉터리는 제외하고 바로 아래의 `.log` 파일만 찾아 출력한 뒤 `-exec ... {} +`로 `archive` 디렉터리에 복사한다.

**완료 기준**: `find`의 시작점, 조건, 동작을 구분하고 `{}`와 `+`, `\;`, `xargs -0`이 필요한 상황을 설명한다.

**참고 노트**: [Ch.20 Searching for Files](../notes/part-03-common-tasks/ch20-searching-for-files.md)

### 9회차: `sed`와 `awk`

**목표**: 줄 단위 변환과 필드 단위 처리를 구분하고 두 도구를 파이프라인에 넣는다.

**상황 실습**: 주석, 빈 줄, 서비스 이름, 상태 코드가 섞인 데이터를 만든다. 주석과 빈 줄을 제거하고 서비스와 코드 필드를 추출해 서비스별 오류 수를 계산한다.

**독립 재현**: `sed`, `awk`, `sort`, `uniq`를 연결해 ERROR 줄의 서비스별 개수를 큰 순서대로 출력한다.

**완료 기준**: `sed`가 줄을 변환하는 방식과 `awk`의 필드, `-F`, 조건, `print`를 설명하고 원본 수정 전 화면에서 결과를 확인한다.

**참고 노트**: [Ch.24 Text Processing](../notes/part-03-common-tasks/ch24-text-processing.md)

### 10회차: 설정 비교, `tar`와 복구

**목표**: 설정 변경 내용을 비교하고 원본과 결과를 압축한 뒤 압축을 풀지 않고 내용을 검증한다.

**상황 실습**: 두 버전의 설정 파일을 만들고 차이를 확인한다. 설정과 보고서를 `tar.gz`로 묶고 목록을 본 뒤 별도 `restore` 디렉터리에 해제한다.

**독립 재현**: 생성, 목록 확인, 해제를 각각 수행하고 원본과 복원 파일이 같은지 비교한다. 실습이 끝난 뒤 `c`, `x`, `t`, `z`, `f`의 의미를 노트 없이 설명한다.

**완료 기준**: `diff -u`, `tar czf`, `tar tzf`, `tar xzf`를 직접 사용하고 기존 `tar` 오답 질문에 다시 맞힌다.

**참고 노트**: [Ch.21 Archiving and Backup](../notes/part-03-common-tasks/ch21-archiving-and-backup.md), [Ch.24 Text Processing](../notes/part-03-common-tasks/ch24-text-processing.md)

## 3주 차: Bash와 관리 입문

### 11회차: 첫 Bash 스크립트

**목표**: 여러 명령을 파일에 저장하고 Bash로 해석하거나 실행 파일로 직접 실행한다.

**상황 실습**: `nano`로 현재 시간, 작업 디렉터리, 파일 수를 출력하는 스크립트를 작성한다. `bash script.sh`와 `./script.sh`를 각각 실행하고 필요한 조건을 비교한다.

**독립 재현**: 새 파일에 shebang과 세 개의 명령을 작성하고 실행 권한을 부여한 뒤 `./`로 실행한다. 성공한 명령의 종료 상태도 확인한다.

**완료 기준**: shebang, 실행 권한, `./`, `PATH`, 종료 상태가 명령 실행에 미치는 영향을 설명한다.

**정식 진도**: 이 회차는 복구 과정으로만 기록하며 Ch.28을 완료로 표시하지 않는다.

### 12회차: 인자, 입력과 조건문

**목표**: 스크립트가 받은 인자를 확인하고 파일 상태에 따라 다른 행동을 선택한다.

**상황 실습**: 파일 경로를 첫 번째 인자로 받는다. 인자가 없거나 파일을 읽을 수 없으면 이유를 stderr에 출력하고 실패 상태로 종료하며, 정상 파일이면 종류에 맞는 요약을 출력한다.

**독립 재현**: `$#`, `$1`, 따옴표, `test` 또는 `[[ ]]`, `if`, `case`를 사용해 정상 입력과 잘못된 입력을 모두 처리한다.

**완료 기준**: 위치 인자와 종료 상태를 설명하고 공백이 있는 경로, 누락된 인자, 존재하지 않는 파일을 안전하게 처리한다.

**정식 진도**: 이 회차는 복구 과정으로만 기록하며 관련 Part 4 챕터를 완료로 표시하지 않는다.

### 13회차: 반복문, 함수와 디버깅

**목표**: 여러 파일에 같은 작업을 반복하고 공통 동작을 함수로 묶으며 문법과 실행 흐름을 확인한다.

**상황 실습**: 디렉터리 안의 로그 파일을 반복하면서 파일 이름과 ERROR 줄 수를 출력한다. 한 파일을 검사하는 동작은 함수로 분리한다.

**독립 재현**: `for` 또는 `while` 반복문과 함수를 사용해 세 파일을 처리한다. `bash -n`으로 문법을 확인하고 필요한 구간만 `set -x`로 추적한다.

**완료 기준**: 반복 대상, 함수의 인자와 반환 상태, `bash -n`과 `set -x`의 차이를 설명하고 오류가 있는 스크립트를 수정한다.

**정식 진도**: 이 회차는 복구 과정으로만 기록하며 관련 Part 4 챕터를 완료로 표시하지 않는다.

### 14회차: 로컬 서버의 프로세스, 포트와 로그 진단

**목표**: 서비스가 응답하지 않는 상황에서 프로세스, 포트, 요청과 로그를 순서대로 확인한다.

**상황 실습**: 임시 디렉터리에서 `python3 -m http.server`를 1024보다 큰 포트로 실행하고 stdout과 stderr를 로그 파일에 저장한다. `ps`, `ss`, `curl`로 상태를 확인하고 같은 포트를 다시 사용했을 때 생기는 오류를 진단한다.

**독립 재현**: 실행한 서버의 PID와 수신 포트를 찾고 요청 결과와 로그를 확인한 뒤 기본 `TERM` 신호로 종료한다. 종료 후 포트가 닫혔는지도 검증한다.

**완료 기준**: 프로세스 존재, 포트 수신, HTTP 응답, 로그 확인이 서로 다른 진단 단계인 이유를 설명하고 실습에서 시작한 프로세스를 모두 종료한다.

**환경 제한**: 현재 WSL 세션에서는 systemd 시스템 버스를 사용할 수 없으므로 `systemctl` 실습은 하지 않는다.

### 15회차: 로그 보고서 스크립트 종합 실습

**목표**: 기본 명령, 파이프라인, 입력 검사, 오류 처리와 압축을 하나의 관리용 스크립트로 연결한다.

**과제 인터페이스**: `./service-report.sh INPUT_LOG OUTPUT_DIR` 형태로 실행한다. 정상 입력에서는 `OUTPUT_DIR/error-summary.txt`와 `OUTPUT_DIR/recovery-report.tar.gz`를 만든다.

**정상 동작**: 읽을 수 있는 로그에서 ERROR 줄의 상태 코드별 횟수를 큰 순서대로 정리해 화면과 보고서에 출력한다. 압축 파일에는 입력 로그와 보고서를 넣고 압축을 풀지 않은 채 목록을 확인한다.

**오류 동작**: 인자가 두 개가 아니거나 입력 파일을 읽을 수 없으면 이유를 stderr에 출력하고 0이 아닌 상태로 종료한다. 출력 디렉터리가 없으면 안전하게 생성한다.

**검증**: `bash -n`을 통과하고 공백이 있는 입력 경로에서도 동작해야 한다. 정상 입력, 인자 누락, 존재하지 않는 파일을 각각 실행해 종료 상태와 생성된 파일을 확인한다.

**완료 기준**: 최소 네 단계의 파이프라인과 입력 검사를 정답 예제 없이 작성하고, 각 명령의 입력과 출력, 실패 시 동작을 설명한다.

## 세션 기록

각 회차가 끝나면 `progress/logs/YYYY-MM-DD.md`에 다음 내용만 짧게 기록한다.

- 수행한 핵심 작업과 독립 재현 성공 여부
- 사용한 힌트 단계: 없음, 개념, 구조, 최소 예제
- 예상과 실제 결과가 달랐던 지점
- 다음 세션에서 먼저 다시 할 작업 한 가지

실제로 틀리거나 설명하지 못한 항목만 [오답 복습 대기열](review-queue.md)에 추가한다. 관련 회차에서 다시 맞힌 기존 항목은 대기열에서 제거하고 결과를 학습 일지에 남긴다.
